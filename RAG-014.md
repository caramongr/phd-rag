Project: PhD Academic RAG
Task ID: RAG-014
Goal: Build a simple local web UI over the completed RAG-013 mode service.
RAG-001 through RAG-013 are complete.
Project root:
F:\phd-rag

Keep this practical. Do not redesign retrieval, generation, citations, discovery, or modes.
1. UI goal
Build a simple local interface where the user can:
choose mode
type a question
run it
read the answer
inspect sources
inspect references
inspect external discoveries
see warnings

This is primarily for daily PhD use.
2. Required modes
UI selector:
Evidence
Writing
Consistency
Supervisor
Research

These must call the existing RAG-013 ModeService.
Do not duplicate mode logic in the frontend.
3. Technology
Reuse the existing FastAPI application.
Prefer a lightweight frontend:
FastAPI backend
HTML/CSS/vanilla JavaScript

Avoid adding React/Vue/build tooling unless there is a strong existing reason.
The UI should run locally with one command.
4. Main screen
Required:
mode selector
large question/input box
Run button
clear/reset button
status/loading indicator
answer panel

Keep it clean and readable.
5. Mode descriptions
Show a short explanation when a mode is selected:
Evidence
Answers from scholarly literature only.

Writing
Drafts academic prose using literature as evidence and your own work/rules as context.

Consistency
Compares your existing work with literature and writing rules.

Supervisor
Searches supervision and guidance material.

Research
Searches your local corpus plus external academic sources.

6. Evidence / Writing output
Show:
validated answer
Harvard references
warnings if partial/uncertain/withheld claims exist

Provide expandable:
Sources
Validation details

For each local source show:
title
author/year
pages
section
DOI when available
role
evidence yes/no
OCR flag
text preview

7. Consistency output
Show findings grouped by:
terminology
duplication
unsupported claims
numeric discrepancies
style

Each finding should show:
description
source/draft excerpt
literature excerpt where relevant
method
warning that "unsupported" means not found in retrieved literature, not necessarily false

Do not auto-rewrite the user's text.
8. Supervisor output
Show labelled excerpts:
[supervision]
[guidance]
[rules]
[future_chapters]

Include:
source file
section
pages if available
excerpt

Clearly state that these are not scholarly evidence.
9. Research output
Keep local and external results visibly separate.
Sections:
LOCAL EVIDENCE
NEW EXTERNAL PAPERS
ALREADY IN CORPUS
POSSIBLE MATCHES
CONFLICTS

External result card:
title
authors
year
venue
DOI
provider(s)
verification status
open-access/fulltext status
abstract preview if available

Show:
NOT IN LOCAL CORPUS

or:
ALREADY IN CORPUS

prominently.
External metadata-only records must never look like validated evidence.
10. Advanced options
Keep advanced controls collapsed by default.
Include only useful ones:
answer length: concise / normal / detailed
candidate_k
final_k
year_min / year_max for Research
include/exclude reranker
show audit

Do not expose every internal configuration value.
11. Source expansion
User should be able to expand a source card and see:
retrieved text
retrieval score
rerank score
chunk id
document id
provenance

This is for debugging/research transparency.
Keep it hidden by default.
12. Copy functionality
Add simple buttons:
Copy answer
Copy answer + references
Copy references

Preserve paragraph formatting.
13. Input for Consistency/Writing
Allow the main input box to contain:
a question
a paragraph
a section of thesis text

No file upload yet unless it is trivial to support without expanding scope.
Do not build document management in this stage.
14. API endpoint
Add a clean endpoint such as:
POST /api/mode

Request:
{
  "mode": "evidence",
  "query": "...",
  "options": {}
}

Response should serialize the existing ModeResult.
Do not create a second result model unless needed only for JSON transport.
15. Health/status
Add a simple status area showing:
Ollama available / unavailable
Qdrant available
generation model
indexed points

Keep status checks lightweight.
Do not reload models just to display status.
16. Error handling
Friendly messages for:
Ollama unavailable
model missing
Qdrant locked/unavailable
Internet provider unavailable
no results
insufficient evidence
generation timeout

Show technical details only under an expandable debug section.
17. Security
Local UI only by default.
Bind by default to:
127.0.0.1

Do not expose on 0.0.0.0 unless explicitly configured.
No authentication is needed for localhost-only operation.
Escape rendered source/user text to prevent HTML injection.
Do not render document HTML as trusted markup.
18. Visual style
Keep it simple:
readable academic interface
light/dark compatible if easy
wide central content area
clear typography
source cards
minimal animation

Do not spend time on elaborate branding.
