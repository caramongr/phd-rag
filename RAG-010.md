Project: PhD Academic RAG
Task ID: RAG-010
Goal: Add controlled Internet-based academic discovery that searches external scholarly sources, identifies material not already present in the local PhD corpus, and keeps external discoveries strictly separate from trusted local evidence.
RAG-001 through RAG-009 are complete.
Do not implement Qwen answer generation, thesis prose generation, Harvard citation rendering, UI, agents, or automatic import into the trusted corpus.
Project root:
F:\phd-rag

1. Core principle
The system now has two fundamentally different knowledge domains:
LOCAL TRUSTED CORPUS
  indexed and classified material
  RAG-009 retrieval

EXTERNAL DISCOVERY
  Internet results
  not trusted by default
  not automatically scholarly evidence

Never silently mix them.
An Internet result is not evidence merely because a search API returned it.
2. External source statuses
Introduce explicit statuses such as:
LOCAL_MATCH
EXTERNAL_DISCOVERY
EXTERNAL_METADATA_VERIFIED
EXTERNAL_FULLTEXT_VERIFIED
UNAVAILABLE
CONFLICT

Meanings:
LOCAL_MATCH
  already present in the user's corpus

EXTERNAL_DISCOVERY
  found online, identity not sufficiently verified

EXTERNAL_METADATA_VERIFIED
  identity and bibliographic metadata confidently verified

EXTERNAL_FULLTEXT_VERIFIED
  actual paper/content acquired and identity verified

UNAVAILABLE
  known result but required metadata/content unavailable

CONFLICT
  external sources disagree about identity/metadata

Do not call anything trusted merely because metadata matches.
3. Providers
Implement provider adapters, not provider-specific logic scattered throughout the code.
Required first-class providers:
Crossref
OpenAlex

Optional adapters may be added cleanly for:
Semantic Scholar
Scite

but they must not block RAG-010 if credentials/API access are unavailable.
Do not add unnecessary scraping frameworks.
4. Provider interface
Create something conceptually similar to:
class AcademicDiscoveryProvider:    search(query, filters) -> list[ExternalRecord]    lookup_doi(doi) -> ExternalRecord | None    provider_name


Keep provider-specific response models behind adapters.
The rest of the application should operate on one normalized external record model.

7. Local corpus comparison
Every external discovery must be compared against the local RAG corpus.
Matching priority:
1. exact normalized DOI
2. exact/very strong normalized title
3. title + year + first-author consistency

Reuse RAG-006 identity/matching concepts where appropriate.
Do not create a second inconsistent document-matching system.
External result output should clearly say:
already_in_corpus = true/false

and when true:
local_document_id
local_filename
local_file_hash
match_reason

8. DOI normalization
Reuse the existing RAG-006 DOI normalization rules.
These must match:
10.xxxx/abc
https://doi.org/10.xxxx/abc
DOI:10.xxxx/abc

Do not implement a competing DOI parser.
9. Duplicate external results
Several providers may return the same paper.
Deduplicate external results by:
DOI first
strong title identity second

Merge provider provenance rather than keeping several copies.
Example:
providers = [crossref, openalex]

Preserve conflicts instead of silently choosing one value.
10. Provider precedence
Do not assume one provider is universally authoritative.
Use field-level provenance.
Example:
DOI        Crossref
cited_by   OpenAlex
OA status  OpenAlex
abstract   provider that actually supplies it

If title/year/authors conflict materially:
status = CONFLICT

rather than silently overwriting.
11. OpenAlex API handling

Support:
PHD_RAG_OPENALEX_API_KEY
PHD_RAG_OPENALEX_EMAIL

where appropriate.
If no key exists:
continue with available anonymous access

but a 429 must:
be reported
not crash the whole discovery request
not fabricate results
allow other providers to continue

Do not describe API quota as money charged to the user.
12. Crossref etiquette/configuration

14. Cache
External discovery must be cached.
Cache key should include at least:
provider
normalized query / DOI
filters
provider request version

Cache raw provider response or sufficiently complete normalized response.
Provide TTL/configuration.
A repeated academic search should not unnecessarily hit the Internet again.
Add:
--refresh

to bypass valid cache deliberately.

16. Do not automatically import
RAG-010 must not:
download arbitrary PDFs into data/
modify the trusted corpus
create embeddings for web results
add external records to Qdrant
mark web results as literature evidence

Import/acceptance will be an explicit later action.
Discovery is read-only with respect to the PhD corpus.
17. Full-text discovery
Where a provider supplies an open-access or publisher URL, preserve it.
Support classification such as:
FULLTEXT_OPEN
LANDING_PAGE_ONLY
UNKNOWN

Do not circumvent publisher access controls or authentication.
Do not claim full text was verified unless the content was actually retrieved and associated with the correct paper.
18. Optional full-text verification
Add an explicit optional operation:
verify_fulltext(record)

It may follow legitimate open-access PDF/full-text URLs.
For RAG-010 this is for verification/preview only.
Do not permanently import the content.
If successfully fetched:
verify DOI/title identity
record content hash
record source URL
record retrieval timestamp

Never silently replace the metadata record with downloaded content.
19. Ranking external discoveries
External ranking should consider:
query/title relevance
abstract relevance where present
exact DOI/title identity
publication year
metadata completeness

Do not rank solely by citation count.
Citation count may be shown as contextual information but is not a truth/relevance score.
Keep ranking deterministic.

29. Security
External URLs are untrusted input.
For any optional full-text fetch:
allow http/https only
reject file://
reject localhost
reject loopback/private-network targets
enforce timeouts
limit download size
validate content type

Protect against redirects to private/local addresses.
Do not execute downloaded content.
