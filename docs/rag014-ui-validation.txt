                    undefined, and the page contained 0 injected img or script elements.
  Error shapes      (live HTTP against the running server)
                    backwards year range  → 422 {"kind":"invalid_request",
                                               "detail":"options: Value error, year_min must
                                                         not be later than year_max"}
                    empty query           → 422 "query: Value error, the query is empty"
                    unknown mode          → 422 "mode: Input should be 'evidence', 'writing',
                                                          'consistency', 'supervisor' or 'research'"
                    unknown option        → 422 "options.temperature: Extra inputs are not permitted"

                    served page and the API were both reachable while /health answered.

  Failures that cannot be produced without breaking the machine are covered by tests instead

  the collapsed debug panel.

OPERATIONAL NOTE
  A local Qdrant store can be held by one client per process, so the UI and a CLI run cannot
  both open the same index directory at the same time. This was observed while validating:
  with the UI server running, a CLI test that opens the store failed on the lock and passed
  again as soon as the server stopped. Start the UI when you want the UI, and use the CLI when
  you want the CLI (or point one of them at a Qdrant server).
