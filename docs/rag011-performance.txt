TOKEN-ESTIMATE CALIBRATION
  The context budget uses a deterministic estimate, max(chars/4, words*1.33) plus 32 tokens per block. Against Ollama's real prompt_eval_count the estimate is consistently about 29% high (measured ratio 0.777 in every run above), i.e. it over-estimates rather than under-estimates, which is the safe direction for a budget. The real prompt is about 5.5k tokens for an 8-chunk evidence context, so the 6000-token budget and the 8192-token window have headroom.

WHAT DOMINATES
  With a warm cache of models and a resident generation model, a normal answer costs about 2.2 s of which 1.8 s is generation. A detailed answer costs about 4.2 s. No optimisation was attempted: the numbers were measured first, and a 35B MoE model at ~227 tokens per second is already the practical limit here. Loading the models (about 11.5 s) dominates any single CLI invocation and is unavoidable in a one-shot process.

  Video memory: 29.2 GiB of 32.6 GiB is in use while the model is resident with num_ctx=8192, leaving roughly 3.4 GiB. Raising num_ctx to 16384 would add about 2.5 GiB of KV cache and should still fit, but 8192 was kept because the measured evidence context is about 5.5k tokens.
