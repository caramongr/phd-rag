Project: PhD Academic RAG
Task ID: RAG-006
Goal: Implement academic document metadata extraction and controlled enrichment, with explicit provenance and confidence.
This task must identify document-level metadata such as title, authors, year, DOI, venue, and publication type without silently inventing anything.
Do not implement chunking, embeddings, Qdrant, reranking, generation, Harvard citation formatting, or UI.

- Python 3.12
- FastAPI
- Pydantic v2
- PyMuPDF
- python-docx
- Existing RAG-001 to RAG-005 architecture must remain intact.

2. Metadata is not all equally trustworthy
Every metadata field must record where it came from.
Add a controlled enum such as:
MetadataSource

Possible values:
PDF_METADATA
DOCX_PROPERTIES
FILENAME
DOCUMENT_TEXT
CROSSREF
OPENALEX
MANUAL

Do not collapse these into one source label.
The system must be able to distinguish:
title from PDF metadata

from:
title inferred from first-page text

from:
title verified by Crossref

3. Metadata field model
Introduce a reusable model such as:
MetadataValue[T]
├── value
├── source
├── confidence
└── evidence

or an equivalent clean design.
confidence may be a controlled level rather than arbitrary floating-point pseudo-precision.
Preferred:
HIGH
MEDIUM
LOW

Do not invent numeric confidence scores unless they are actually meaningful.
evidence may contain concise provenance such as:
PDF metadata field "title"
first page DOI pattern
Crossref DOI lookup

Do not store huge excerpts.
4. Academic metadata model
Create or extend a model representing:
AcademicMetadata

Suggested fields:
title
authors
year
doi
venue
publisher
publication_type
url
abstract

Each field should preserve source/provenance.
Not every document will have every field.
Missing is valid.
Never manufacture a value just to complete the record.
5. Publication types
Add a controlled enum if one does not already exist.
Suggested:
JOURNAL_ARTICLE

Folder context may be a hint, not authority.
6. Extraction order
Metadata extraction should follow a deterministic priority chain:
1. explicit structured metadata
2. DOI detection
3. conservative local text extraction
4. external verification/enrichment

Do not call external services before checking local information.
7. PDF embedded metadata
Read fields such as:
title
author
subject
keywords
creator
producer
creationDate

Preserve useful fields but do not assume they are correct.
Examples:
"Microsoft Word - document1.docx"
"untitled"
"Adobe PDF"

are not meaningful academic titles.
Implement a conservative validity check for metadata titles.
Reject obviously useless values such as:
untitled
document
Microsoft Word
Acrobat
scanner-generated filenames

Do not over-clean legitimate titles.
8. DOI extraction
Detect DOI strings from:
PDF metadata
first pages
last pages / references if necessary
filename

Use a robust DOI pattern.
Normalize to canonical form:
10.xxxx/xxxxx

Remove wrappers such as:
https://doi.org/
http://dx.doi.org/
doi:

Preserve the normalized DOI only.
Do not treat every string beginning with 10. as valid without validation.
9. Local title extraction
For PDFs lacking a meaningful embedded title, implement a conservative local title candidate extractor from the first page.
This is a candidate, not automatically authoritative metadata.
Prefer signals such as:
prominent first-page text
text near top of page
reasonable academic-title length
not journal header
not DOI
not author affiliation
not copyright line

Font size may be used here because this task is metadata extraction, unlike earlier structural parsing.
Still:
- do not use an LLM;
- do not guess aggressively;
- do not assume the largest text is always the title;
- store source as DOCUMENT_TEXT;
- confidence should usually be MEDIUM until externally verified.
If uncertain, leave title missing.
10. Author extraction
Extract authors conservatively.
Sources may include:
PDF metadata author field
first-page author lines
Crossref
OpenAlex

Do not interpret affiliations as authors.
Preserve author ordering where possible.
Suggested normalized representation:
Author
├── given_name
├── family_name
├── full_name
├── orcid optional

If parsing given/family names is unreliable, preserve full_name without inventing parts.
11. Year extraction
Possible local sources:
PDF metadata creation date
publication line
DOI landing metadata
copyright line
first-page citation information

Do not treat PDF file creation date as publication year with HIGH confidence.
Example:
PDF creationDate = 2024
paper publication = 2019

The publication year should be 2019.
Source provenance must distinguish them.
12. Venue extraction
Venue may mean:
journal
conference
book title
institution for thesis/report

Prefer external structured metadata when available.
Local extraction should be conservative.
13. External enrichment
Add controlled support for:
Crossref
OpenAlex

External requests are allowed only in this metadata stage.
Do not add broad web scraping.
Use APIs only for bibliographic metadata.
14. External lookup priority
If DOI exists:
DOI
  ↓
Crossref exact lookup
  ↓
OpenAlex DOI lookup if useful

This should be the highest-confidence enrichment route.
If no DOI exists:
use a conservative title-based lookup only when a strong title candidate exists.
Do not perform fuzzy lookup against every random first-page string.
15. Matching rules
External results must not be accepted solely because one result was returned.
For title-based matching, compare normalized:
title
year if known
first author if known

Require a strong match.
If ambiguous:
external_match_status = AMBIGUOUS

and do not overwrite local metadata.
Suggested enum:
EXACT
STRONG
AMBIGUOUS
NO_MATCH

16. Never silently overwrite metadata
If local metadata says:
title = X

and Crossref says:
title = Y

preserve the provenance of both candidates.
A resolved/preferred value may be selected, but the underlying candidate history must remain inspectable.
Do not destructively replace metadata.
17. Metadata resolution
Add a deterministic resolver.
Preferred priority:
exact DOI-verified Crossref/OpenAlex metadata
> strong structured publisher metadata
> meaningful embedded PDF metadata
> strong local first-page candidate
> filename-derived candidate

This priority may vary by field.
For example:
- PDF embedded title may be useful.
- PDF creation year is weak.
- Crossref publication year is strong.
Implement field-specific resolution rules rather than one simplistic global ordering.
18. Filename metadata
Filename is a weak fallback only.
Examples:
kerbl-2023.pdf
Zhu-1703.10593v7.pdf

Filename may help identify:
author-like token
year-like token
arXiv identifier

but should be LOW confidence unless externally verified.
Do not transform filenames into authoritative titles.
19. arXiv support
Detect arXiv identifiers where obvious, for example:
1703.10593
2308.04079

Normalize and preserve:
arxiv_id

If OpenAlex or Crossref does not resolve a preprint, leave it unresolved rather than adding a new broad API unless necessary.
Do not add arXiv API integration yet unless it is trivial and clearly justified.
20. Author's own work
Documents under:
data\my_work\

must not be sent to Crossref/OpenAlex by default unless they have a DOI or are known published works.
A thesis draft or current paper should remain:
AUTHOR_MANUSCRIPT

with metadata primarily from:
DOCX properties
explicit title text
folder context
manual metadata later

Do not misclassify the user's draft as an external publication.
21. Guidance, supervision and rules
Files under:
data\rules\
data\supervision\
data\future_chapters\
data\summaries\

must not be treated as scholarly publications merely because they contain titles and authors.
Preserve their existing source-role semantics.
Do not query Crossref/OpenAlex for:
writing guidelines
supervision records
future chapter guidance
internal summaries

unless explicitly requested later.
22. Duplicate documents
RAG-002 already identifies duplicates by SHA-256.
Metadata enrichment should operate on the logical unique document, not every physical copy independently.
All physical locations should point to the same resolved academic metadata where they share the same hash.
Do not waste API calls on binary-identical duplicates.
23. Rate limiting and caching
External metadata APIs must be used responsibly.
Implement:
request timeout
retry with bounded backoff
rate limiting
lightweight response cache

Cache key should preferably use:
DOI

or normalized lookup parameters.
A simple local JSON cache is acceptable for RAG-006.
Do not introduce a database just for metadata caching.
24. Offline mode

Add a mode such as:
enrich_external=False

In offline mode:
local metadata extraction still works
no Crossref/OpenAlex requests occur
