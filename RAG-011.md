5. Internet discoveries
RAG-010 external discoveries must remain separate.
They may be supplied to generation only as:
EXTERNAL_DISCOVERY

or:
EXTERNAL_METADATA_VERIFIED

unless actual full text has been verified.
Metadata-only Internet results must not support substantive factual claims.
Example:
Allowed:
"A 2026 paper with this title was found and may be relevant."

Not allowed:
"The paper found that students improved by 27%."

unless the supporting content was actually retrieved and verified.
Local evidence remains the default evidence source.
6. Context builder
Build a deterministic context package from retrieved chunks.
Each source block should have an internal source identifier:
[S1]
[S2]
...

Example:
[S1]
Title: ...
Author: ...
Year: ...
DOI: ...
Pages: 4-6
Section: ...
Evidence eligible: true
OCR: false
Text:
...

The model must reference these IDs during generation.
Do not rely on Qwen remembering metadata separately.
7. Context budget
Do not blindly send every retrieved chunk.
Implement a configurable context budget.
Estimate/model-count tokens before generation.
Preserve the best-ranked evidence first.
Never truncate a chunk silently in the middle without reporting it.
Prefer dropping the lowest-ranked complete source block.
Record:
retrieved chunks
included chunks
excluded due to budget
context token count

Qwen currently supports a large context window, but the application must not depend on unlimited context.
8. Weak-result handling
RAG-009 showed that weak tail results can have very low reranker scores.
Do not force Qwen to use weak evidence simply because final_k=8.
Implement generation-time evidence selection.
Do not pick an arbitrary universal threshold without testing.
Start with an explicit configurable:
min_generation_rerank_score

default:
None

Then evaluate real retrieval results and recommend a threshold if supported by data.
The answer generator should also be able to say:
insufficient evidence

rather than filling gaps.
9. Grounding rules
System prompt must make these rules explicit:
Use only supplied evidence for factual claims.

Do not invent studies, statistics, authors, years, findings or quotations.

If the evidence does not support a requested claim, say so.

Distinguish evidence from interpretation.

Do not treat the user's own drafts as external scholarly evidence.

Do not treat summaries, supervision notes, rules or future chapter guidance as scholarly evidence.

Do not treat external metadata-only search results as evidence of findings.

Avoid overclaiming.

10. Answer style
For academic answers use the user's preferred style:
plain academic prose
short, varied sentences
clarity over sophistication
no em dash character
no promotional language
no unnecessary jargon
no invented conclusions

This stage does not yet need final Harvard bibliography formatting.
11. Claim-level source markers
Every substantive generated claim must carry one or more temporary source markers:
[S1]
[S2]
[S1,S4]

These are internal grounding markers, not final Harvard citations.
Example:
AI governance in higher education increasingly includes institutional
policy, accountability and ethical oversight [S2,S5].

RAG-012 will validate and convert these later.

13. No source-marker invention
After generation, parse every [Sx].
Hard rule:
every referenced Sx must exist in the supplied context

Unknown source IDs must trigger:
invalid_source_marker

Do not silently remove them and pretend the answer is grounded.
14. Unsupported-answer behaviour
Prompt Qwen to use language such as:
"The retrieved evidence does not provide enough support to answer this confidently."

when necessary.
This is preferable to hallucinating.
Test questions whose answers are absent from the corpus.
15. Quotations
Do not encourage direct quotation.
If Qwen produces a quotation:
preserve source ID
require page provenance where available
mark it for later RAG-012 validation

Do not fabricate quotation marks around paraphrases.
16. OCR evidence
OCR-derived chunks may be used, but the answer result must preserve:
ocr_involved = true

so RAG-012 can apply stronger checking.
Do not hide OCR provenance from downstream stages.
17. Table evidence
If a retrieved chunk is:
content_type = table

preserve that fact in the context.
Qwen may summarize a table, but must not invent values not present in it.
Keep source marker attached.
18. Non-evidence context
Allow explicit optional generation modes for development/testing:
evidence_only
evidence_plus_my_work
evidence_plus_guidance

But do not build the final mode system yet.
Rules:
evidence -> may support scholarly claims
my_work -> continuity/terminology only
guidance -> instructions/planning only

Clearly label each context block.
Qwen's prompt must say which blocks are citable evidence and which are not.
19. Own-work use
Example:
evidence_plus_my_work

should allow:
"Use my existing terminology and avoid contradicting what I already wrote."

But my_work must not become evidence for claims about the world.
