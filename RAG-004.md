Project: PhD Academic RAG
Task ID: RAG-004
Goal: Implement faithful PDF parsing with exact page provenance and structured page/block output.
This task must not implement chunking, embeddings, Qdrant, reranking, Ollama, metadata enrichment from the internet, citation generation, or OCR.
Environment
- Python 3.12
- FastAPI
- Pydantic v2
- PyMuPDF
- Project root: F:\phd-rag
- Preserve all RAG-001, RAG-002, and RAG-003 behavior.
Inspect the existing repository and tests before making changes.
Architectural rules
- Keep extraction explicit and auditable.
- Use PyMuPDF as the primary PDF parser.
- Do not use LangChain, LlamaIndex, Haystack, or another RAG framework.
- Do not call Ollama.
- Do not connect to Qdrant.
- Do not create embeddings.
- Do not perform chunking.
- Do not perform OCR.
- Do not call Crossref, OpenAlex, publishers, or other internet APIs.
- Do not infer unsupported bibliographic facts.
- Source files are strictly read-only.
- Exact page provenance is more important than aggressive structural inference.
- If a PDF cannot be parsed reliably, record the limitation rather than inventing content.
- If an architectural decision is not covered here, stop and report it.
1. Purpose
The real corpus contains approximately:
478 PDF files

PDFs form the main scholarly evidence layer.
RAG-004 must extract readable PDF content while preserving exact page provenance so that later retrieval can answer:
What source did this claim come from?
Which PDF page contains the evidence?
What exact text was retrieved?

Page provenance is mandatory.
2. Extend the normalized parsing architecture
Reuse the existing ParsedDocument architecture from RAG-003 where practical.
Add PDF-specific provenance without breaking DOCX or Markdown.
A PDF should produce:
ParsedDocument
├── source_path
├── filename
├── file_hash
├── extension
├── title
├── blocks[]
├── tables[]
├── content_items[]
├── raw_text
└── page_count

Add page_count to the common model if it can be done without breaking existing behavior.
Existing DOCX/Markdown parsers should remain compatible.
3. Page provenance
Every text block extracted from a PDF must record:
page_number

Use human-readable 1-based page numbers:
first PDF page = 1
second PDF page = 2

Do not expose PyMuPDF's internal zero-based page number directly.
Every block should also have a deterministic:
source_locator

such as:
page:12:block:4

Exact formatting may vary slightly, but it must be deterministic and tested.
4. PDF parser
Add:
app/parsing/pdf_parser.py

Suggested interface:
parse_pdf(path: Path, file_hash: str | None = None) -> ParsedDocument


Requirements:
- use PyMuPDF;
- source file opened read-only;
- process one page at a time;
- preserve page number;
- preserve text order as reliably as practical;
- do not concatenate all pages before provenance is assigned;
- skip empty text blocks where appropriate;
- preserve Unicode;
- preserve Greek characters;
- preserve citation strings;
- preserve punctuation and symbols;
- produce raw_text;
- report page_count;
- do not modify the PDF.
5. Extraction granularity
Do not treat an entire page as one giant paragraph unless that is the only reliable extraction available.
Use PyMuPDF's structured extraction mode such as:
page.get_text("dict")

or another appropriate structured mode.
Prefer meaningful text blocks derived from the PDF's text layout.
Each extracted block should preserve:
block_index
page_number
text
source_locator

If useful and reliable, preserve layout information such as:
bbox

but do not make bounding boxes mandatory unless they improve the design cleanly.
6. Reading order
PDF reading order can be difficult.
Use PyMuPDF's available ordering information and a deterministic strategy.
The parser should aim to preserve natural reading order:
top-to-bottom
left-to-right

where practical.
Do not build a complicated layout-analysis engine in RAG-004.
If two-column papers are imperfectly ordered, report this limitation rather than introducing large dependencies.
Add tests for deterministic order.
7. Page separators in raw_text
raw_text must preserve page boundaries.
Use a deterministic separator, for example:
[PAGE 1]

...

[PAGE 2]

...

or another clean internal representation.
This will help later debugging and re-processing.
Do not rely on raw concatenation without page markers.
8. PDF title handling
Do not guess titles from arbitrary first-page text.
Allowed deterministic sources:
1. PDF metadata title, if non-empty and meaningful;
2. otherwise None.
Do not automatically classify the largest first-page font as the paper title in RAG-004.
More advanced metadata extraction belongs to RAG-006.
9. Page-level model
Add a page representation if useful.
Suggested model:
ParsedPage
├── page_number: int
├── blocks: list[ParsedBlock]
├── tables: list[ParsedTable]
├── raw_text: str
└── character_count: int

I prefer adding this model because page-level provenance is fundamental for academic evidence.
ParsedDocument may then include:
pages: list[ParsedPage]

while still retaining flattened:
blocks
tables
content_items

for compatibility with later processing.
If this causes a conflict with the current model, stop and report it rather than redesigning independently.
10. Header/footer repetition
Do not automatically remove headers and footers in RAG-004.
Repeated journal headers, page numbers, DOI banners, etc. may appear in extracted text.
Preserve them for now.
Header/footer detection and cleanup can be added later after we inspect the real corpus.
Do not risk deleting meaningful text.
11. Hyphenation
Do not aggressively de-hyphenate words across line boundaries yet.
Preserve extracted text faithfully.
Later normalization can handle cases such as:
educa-
tion

if needed.
RAG-004 should prioritize provenance and fidelity over text rewriting.
12. Tables
Use PyMuPDF table extraction only if it is available and reliable in the installed version.
If table extraction is straightforward:
ParsedTable
├── table_index
├── page_number
├── rows
├── source_locator
└── sequence_index

If reliable table extraction is not available for a PDF, do not invent structure.
Preserve visible table text as normal extracted content.
Report the limitation.
Do not add Camelot, Tabula, OCR, Java, or another large table dependency in this task.
13. References section
Do not remove the bibliography/references section.
RAG-004 is a parser, not a retrieval filter.
If headings such as:
References
Bibliography
Works Cited

can be detected deterministically from extracted text, they may be represented as headings.
But do not exclude or suppress their contents.
Later chunking/retrieval logic will decide whether reference sections participate in normal retrieval.
14. Conservative heading detection
PDF headings are harder than DOCX headings.
Do not implement broad visual heuristics in this task.
Allow only conservative deterministic heading recognition where strong signals exist.
Examples:
1. Introduction
2.1 Background
3 Methods
References
Conclusion

Strong structural text patterns may produce:
ParsedBlockType.HEADING
heading_source = INFERRED

but:
- do not use font size alone;
- do not use bold alone;
- do not use an LLM;
- if uncertain, keep content as ordinary text.
It is acceptable for many PDFs to have few or zero detected headings.
Page provenance is more important.
15. Scanned/image PDFs
Detect pages that contain little or no extractable text.
For example, a page may have:
images present
extracted text empty/nearly empty

Mark this condition explicitly where practical.
Suggested page field:
text_extraction_status:
TEXT
EMPTY
POSSIBLY_SCANNED

Do not perform OCR in RAG-004.
We need to know how many corpus PDFs/pages might need OCR before deciding whether to build that layer.
16. Encrypted PDFs
Handle encrypted/password-protected PDFs explicitly.
Do not crash the entire parsing process.
Raise a clear:
DocumentParseError

or a more specific typed exception if appropriate.
Preserve the source path in the error.
Do not attempt password guessing.
17. Corrupt PDFs
Corrupt or malformed PDFs must produce a clear parse error.
Do not return a successful empty document for a parsing failure.
