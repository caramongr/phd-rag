3. ParsedDocument
Suggested fields:
ParsedDocument
├── source_path: str
├── filename: str
├── file_hash: str | None
├── extension: str
├── title: str | None
├── blocks: list[ParsedBlock]
├── tables: list[ParsedTable]
└── raw_text: str

Notes:
- file_hash may be supplied from RAG-002 where available.
- raw_text should preserve the document's extracted readable content in order.
- title should only be populated when it can be derived deterministically from explicit structure, not guessed.
- Do not invent academic metadata such as authors, year, DOI, or publication status.

5. Heading hierarchy
This is important.
Track heading context as documents are parsed.
Example:
Heading 1: Chapter 4
Heading 2: Development of VR
Heading 3: Early immersive systems

A paragraph under that section should carry:
heading_path:
- Chapter 4
- Development of VR
- Early immersive systems

If the next Heading 2 is:
Evidence of educational use

the Heading 3 context should be cleared appropriately.
The parser must maintain correct hierarchical heading state.
6. DOCX parser
Add:
app/parsing/docx_parser.py

Suggested public interface:
parse_docx(path: Path, file_hash: str | None = None) -> ParsedDocument


Requirements:
- use python-docx;
- open files read-only;
- preserve document order;
- detect Word heading styles such as:
Heading 1
Heading 2
Heading 3
...

- preserve paragraph text;
- ignore completely empty paragraphs unless they have structural significance;
- preserve list-item text when detectable;
- preserve tables;
- maintain heading hierarchy;
- generate deterministic block indexes;
- generate raw_text;
- do not modify the source DOCX.
7. DOCX title handling
Do not infer a title from arbitrary body text.
Allowed deterministic title sources:
1. a paragraph explicitly styled as Title;
2. optionally document core properties title, if present;
3. otherwise None.
Do not automatically use the first paragraph as the title.
8. DOCX tables
Preserve tables separately from prose.
Suggested model:
ParsedTable
├── table_index: int
├── rows: list[ParsedTableRow]
├── heading_path: list[str]
└── source_locator: str | None

Each row:
ParsedTableRow
└── cells: list[ParsedTableCell]

Each cell:
ParsedTableCell
└── text: str

Preserve cell text.
Do not flatten the table permanently into paragraph text.
raw_text may include a readable plain-text representation of the table, but the structured table representation must also be retained.
Do not attempt semantic interpretation of tables.
9. DOCX order issue
Word documents can contain interleaved paragraphs and tables.
The parser should preserve document order as accurately as practical.
If python-docx requires lower-level XML traversal to maintain paragraph/table order, use a small explicit helper rather than silently parsing all paragraphs first and tables afterward.
This matters because a table may belong to a specific subsection.
Do not introduce a large dependency merely for this purpose.
10. Markdown parser
Add:
app/parsing/markdown_parser.py

Suggested public interface:
parse_markdown(path: Path, file_hash: str | None = None) -> ParsedDocument


Requirements:
- UTF-8 first;
- handle UTF-8 BOM cleanly;
- preserve heading hierarchy for:
# Heading 1
## Heading 2
### Heading 3

- preserve paragraphs;
- preserve Markdown list items where practical;
- preserve block quotes where practical;
- do not render Markdown into HTML;
- do not remove citation syntax or emphasis markers unnecessarily;
- maintain deterministic block order.
11. Markdown tables
If simple pipe-style Markdown tables are encountered:
| A | B |
|---|---|
| 1 | 2 |

parse them into ParsedTable if it can be done reliably without adding a large framework.
If not implemented in RAG-003, preserve their raw text as blocks and explicitly report that Markdown table structuring is deferred.
Do not silently discard them.
12. Raw text preservation
Every parsed document must have:
raw_text

representing the extracted readable content.
This is important because later versions may re-chunk documents without reparsing the original file.
Do not normalize aggressively.
Preserve:
- paragraph content;
- headings;
- citation text;
- Unicode;
- Greek characters;
- symbols.
Avoid destructive whitespace cleanup.
Basic normalization such as trimming leading/trailing whitespace per paragraph is acceptable.
13. No chunking yet
This task must not create RAG chunks.
ParsedBlock is not a Chunk.
Parsing answers:
What does the document contain and where?

Chunking later answers:
How should that content be grouped for retrieval?

Keep those stages separate.
14. Source provenance
For DOCX and Markdown, page numbers are generally unavailable or unreliable.
Do not fabricate page numbers.
Use structural provenance instead:
filename
block_index
paragraph_index
heading_path
table_index

source_locator may use readable values such as:
paragraph:14
table:2
heading:3

Exact formatting is your implementation choice, but it must be deterministic.
15. Parse dispatcher
Add a simple dispatcher:
app/parsing/parser.py

Suggested interface:
parse_document(path: Path, file_hash: str | None = None) -> ParsedDocument


Behavior:
.docx -> DOCX parser
.md   -> Markdown parser

Unsupported formats must raise a clear typed exception such as:
UnsupportedDocumentFormat

Do not silently return empty content.
16. Parse errors
Create explicit parse exceptions, for example:
DocumentParseError
UnsupportedDocumentFormat

A corrupt DOCX should produce a clear parse error.
A missing file should produce a clear filesystem-related error or wrapped parse error with the path preserved.
Do not catch every exception and return an empty document.
