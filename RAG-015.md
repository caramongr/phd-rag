PROJECT: PhD Academic RAG
TASK ID: RAG-015-REPAIR
TITLE: Simple persistent chat with attachments and full-context Qwen

Project root:

F:\phd-rag

RAG-001 through RAG-014 already exist.

This is a REPAIR task, not a new architecture project.

The existing advanced RAG functionality must remain available, but the DEFAULT user experience must become a simple ChatGPT/Ollama-style chat.

Do not redesign retrieval, Qdrant, metadata, citation validation, discovery, or the existing five RAG-013 modes.

======================================================================
1. MAIN GOAL
======================================================================

Implement a simple default interface with:

- New Chat
- saved chat history
- reopen previous chats
- rename chat
- delete chat
- normal conversation
- Attach File
- persistent attachments
- large Qwen context
- existing PhD corpus available in the background
- existing advanced RAG functionality preserved under Advanced

The normal user should not have to choose Evidence, Writing, Consistency,
Supervisor or Research before asking a question.

The default experience should behave like a normal local AI chat application.

4. PERSISTENT CHAT STORAGE
======================================================================

Implement local persistent conversations.

Use SQLite unless there is a strong existing project reason not to.

Store at least:

Chat:
- id
- title
- created_at
- updated_at

Message:
- id
- chat_id
- role
- content
- created_at
- ordering

Attachment metadata:
- id
- chat_id
- filename
- stored path
- content type
- parsed-text status
- created_at

Required behaviour:

- New Chat creates a clean conversation.
- Chats appear in a left-side history.
- Opening an old chat restores its messages.
- Rename chat.
- Delete chat.
- Messages survive server/browser restart.
- Attachments remain associated with their chat.

Everything stays local.

======================================================================
5. ATTACH FILES TO A CHAT
======================================================================

Support:

- PDF
- DOCX
- TXT
- MD

Reuse the project's existing parsers where appropriate.

Do not build a second parsing architecture.

Important distinction:

ATTACH FILE
= use this file in this conversation

It must NOT:

- copy the file into data/literature
- copy the file into data/my_work
- add it to the permanent corpus
- chunk/embed/index it into Qdrant
- classify it as scholarly evidence automatically

Chat attachments are temporary working documents associated with a saved chat.

Store enough parsed representation so reopening the chat does not require the
user to upload the file again.

Show attached filenames clearly in the UI.

Add basic file-size and extension validation with readable errors.

======================================================================
6. USE LARGE WORKING DOCUMENT CONTEXT
======================================================================

This is important.

For documents attached to the ACTIVE CHAT, do not automatically reduce them
to the old approximately 800-token RAG chunks.

When practical, provide the full parsed document text to Qwen.

Examples:

- thesis section
- LATTICE framework document
- professor feedback
- writing instructions
- a paper the user wants to discuss

The simple-chat path should construct a context approximately like:

SYSTEM / PHD INSTRUCTIONS
+
conversation history
+
attached working documents
+
optional relevant PhD corpus retrieval
+
current user message
+
output headroom

Use the available 262144-token context intelligently.

Implement deterministic context budgeting.

Priority when trimming becomes necessary should be sensible and documented.

For example:

1. system instructions
2. recent/current conversation
3. explicitly attached/current working documents
4. relevant retrieved corpus material
5. older conversation material

Do not silently cut the middle of a document if avoidable.

Record when context material was omitted because of the context limit.

======================================================================
7. NORMAL CONVERSATION BEHAVIOUR
======================================================================

The simple chat should NOT force the RAG-011 behaviour requiring [S1] markers
on every substantive sentence.

It should NOT automatically run RAG-012 after every answer.

It should NOT automatically generate Harvard citations.

It should NOT automatically force Evidence/Writing/Supervisor modes.

The user should be able to speak naturally, for example:

"Read these documents first. We will work paragraph by paragraph."

"Do you think governance belongs in this paragraph?"

"Don't rewrite yet. Give me three observations."

"Now rewrite only the second paragraph."

"Check whether this citation actually supports the sentence."

The model should answer the user's actual instruction.

Existing specialist capabilities may be called explicitly later, but ordinary
conversation must remain ordinary conversation.

======================================================================
8. PHD BACKGROUND CONTEXT
======================================================================

The permanent PhD corpus must remain available.

However, normal chat should not dump arbitrary top-8 chunks into every request
without reason.

Design the simple-chat path so background RAG retrieval can be invoked when:

- the user explicitly asks to consult the PhD literature/corpus
- the question clearly requires information from the permanent corpus
- an advanced option explicitly enables it

Do not make every casual discussion a forced evidence-mode retrieval call.

Keep permanent corpus retrieval clearly distinguishable from attached working
documents.
